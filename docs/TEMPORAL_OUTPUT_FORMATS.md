# Temporal Output Format Configuration

## Overview

GenX now supports multiple output formats for **full time series** temporal data files (when `WriteOutputs: "full"`):
- **CSV** (default): Standard comma-separated values
- **GZIP**: Gzipped CSV for 50-70% storage reduction
- **Parquet**: Apache Parquet format for 80-90% storage reduction and faster I/O

**Note:** Annual outputs (when `WriteOutputs: "annual"`) are always written as CSV files regardless of the `TemporalOutputFormat` setting.

## Configuration

Add the `TemporalOutputFormat` setting to your `genx_settings.yml` file:

```yaml
WriteOutputs: "full"  # Required for format selection to apply
TemporalOutputFormat: "csv"  # Options: "csv", "gzip", or "parquet"
```

If not specified, the default is `"csv"` for backward compatibility.

## Usage Examples

### CSV Format (Default)
```yaml
WriteOutputs: "full"
TemporalOutputFormat: "csv"
```
Output files: `power.csv`, `charge.csv`, etc.

### Gzipped CSV Format
```yaml
WriteOutputs: "full"
TemporalOutputFormat: "gzip"
```
Output files: `power.csv.gz`, `charge.csv.gz`, etc.

### Parquet Format
```yaml
WriteOutputs: "full"
TemporalOutputFormat: "parquet"
```
Output files: `power.parquet`, `charge.parquet`, etc.

### Annual Outputs
```yaml
WriteOutputs: "annual"
# TemporalOutputFormat has no effect - always writes CSV
```
Output files: `power.csv`, `charge.csv`, etc. (always CSV)

## Affected Files

This setting applies to **full time series** temporal output files generated by `write_temporal_data()` when `WriteOutputs: "full"`:
- `power.csv` / `power.csv.gz` / `power.parquet` (full time series only)
- `charge.csv` / `charge.csv.gz` / `charge.parquet` (full time series only)
- `storage.csv` / `storage.csv.gz` / `storage.parquet` (full time series only)
- `curtailment.csv` / `curtailment.csv.gz` / `curtailment.parquet` (full time series only)
- `emissions_plant.csv` / `emissions_plant.csv.gz` / `emissions_plant.parquet` (full time series only)
- And other time-series outputs (full time series only)

**Important:** When `WriteOutputs: "annual"`, all temporal outputs are written as CSV files regardless of the `TemporalOutputFormat` setting.

## Reading Compressed Outputs

### Gzipped CSV Files
Gzipped CSV files can be read with standard tools:

**Julia:**
```julia
using CSV, DataFrames, CodecZlib
df = CSV.read(transcode(GzipDecompressor, read("power.csv.gz")), DataFrame)
```

Or using DuckDB (from this PR):
```julia
using GenX
df = GenX.load_dataframe("power.csv.gz")
```

**Python:**
```python
import pandas as pd
df = pd.read_csv("power.csv.gz")  # pandas handles .gz automatically
```

**Command line:**
```bash
gunzip -c power.csv.gz | head  # View without decompressing
zcat power.csv.gz > power.csv  # Decompress to CSV
```

### Parquet Files

**Julia:**
```julia
using GenX  # Uses DuckDB internally
df = GenX.load_dataframe("power.parquet")
```

**Python:**
```python
import pandas as pd
df = pd.read_parquet("power.parquet")
```

**R:**
```r
library(arrow)
df <- read_parquet("power.parquet")
```

## Storage Savings

Typical storage reduction compared to CSV:
- **Gzip**: 50-70% smaller
- **Parquet**: 80-90% smaller (for large numerical datasets)

Example for a 100 MB CSV file:
- CSV: 100 MB
- GZIP: 30-50 MB
- Parquet: 10-20 MB

## Performance Considerations

### Gzip
- **Pros**: Widely compatible, good compression
- **Cons**: Slower to read/write than CSV
- **Best for**: Archival storage, sharing via email/download

### Parquet
- **Pros**: Excellent compression, fast columnar reading, industry standard
- **Cons**: Requires specialized libraries to read
- **Best for**: Large datasets, data analysis workflows, cloud storage

### CSV
- **Pros**: Universal compatibility, human-readable
- **Cons**: Large file sizes
- **Best for**: Small datasets, debugging, manual inspection

## Backward Compatibility

- If `TemporalOutputFormat` is not specified, the default is `"csv"`
- Existing workflows will continue to work without modification
- The setting only affects temporal data outputs (time-series files)
- Other outputs (costs, capacity, etc.) remain as CSV

## Implementation Details

The implementation uses DuckDB for writing gzipped and Parquet files:
- Gzipped files are written using `COMPRESSION GZIP` option
- Parquet files are written using `FORMAT PARQUET` option
- File paths are properly escaped to prevent SQL injection
- The format is automatically applied to full time series reconstruction outputs
